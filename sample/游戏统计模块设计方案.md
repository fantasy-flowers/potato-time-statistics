# 游戏统计模块设计方案

> 适用项目：PotatoVN 插件脚手架（`PotatoVN.App.PluginBase`，.NET 8 + WinUI 3）
> 关联资产：`sample/游戏时长统计插件界面（含日期选择器） (1).html`（时长统计原型）、状态分布截图（游玩状态/游戏引擎/制作公司）
> 状态：设计方案（待评审）

---

## 1. 需求与目标

为插件新增一个「游戏统计」模块，回答四类问题：

| # | 需求 | 用户问题 | 展示形态 |
|---|------|---------|---------|
| 1 | 游戏库游戏数量 | 库里有几款游戏？ | 概览卡片 |
| 2 | 游玩状态分布 | 各游玩状态各有多少款？ | 多标签分布（游玩状态/游戏引擎/制作公司） |
| 3 | 总时长最长游戏 | 哪款游戏玩得最久？ | Top1 高亮 + TopN 排行 |
| 4 | 游玩强度热力图 | 每天/每年玩得多狠？ | GitHub 贡献图风格，按年度切换 |

**核心设计取向**：全部统计**实时计算**自宿主游戏库数据，模块**不维护独立游戏表、不做时长埋点**。数据由 PotatoVN 宿主本身持续记录（启动游戏自动累加），模块只负责读取与聚合，天然与宿主数据同步、零数据迁移成本。

---

## 2. 数据基础（已核实的宿主数据）

模块的全部输入来自宿主 API `IPotatoVnApi.GetAllGames()`，返回 `List<Galgame>` 快照。每款 `Galgame` 自带所需字段：

| 字段 | 类型 | 说明 | 对应需求 |
|------|------|------|---------|
| `Name` / `CnName` | string | 游戏名 | 展示 |
| `PlayType` | `PlayType` 枚举 | 游玩状态 | 需求 2 |
| `TotalPlayTime` | int（分钟） | 累计总时长 | 需求 3 |
| `PlayedTime` | `Dictionary<string, int>` | **日期字符串 → 当日游玩分钟数**（key 为 `ShortDateString`） | 需求 4 |
| `Engine` | string | 游戏引擎 | 分布扩展 |
| `Developer` | string | 制作公司 | 分布扩展 |
| `LastPlayTime` | DateTime | 上次游玩时间 | 辅助 |

**关键发现**：`Galgame.PlayedTime` 字典天然就是热力图的明细数据——把库内所有游戏的 `PlayedTime` 按日期聚合求和，即可得到「某天总游玩分钟数」，无需任何额外采集。

`PlayType` 六种取值与中文标签映射（沿用截图顺序）：

| 枚举 | 中文 | | 枚举 | 中文 |
|------|------|---|------|------|
| `None` | 未设置 | | `Shelved` | 搁置 |
| `Played` | 玩过 | | `Abandoned` | 抛弃 |
| `Playing` | 在玩 | | `WantToPlay` | 想玩 |

## 3. 模块架构

在现有插件工程内新增以下文件（不修改宿主 `GalgameManager.WinApp.Base`）：

```
PotatoVN.App.PluginBase/
├── Services/
│   └── GameStatsService.cs          # 统计聚合服务（纯逻辑，无 UI 依赖，可单测）
├── Models/
│   ├── GameStats.cs                 # 聚合结果 DTO（库总数/状态分布/Top/热力图矩阵）
│   └── PluginData.cs                # 扩展：热力图年份偏好、色阶档位（带 Version 字段）
└── Controls/
    ├── GameStatsPage.xaml/.cs       # 模块主页面（侧边栏入口的跳转目标，Page）
    └── Controls/
        ├── StatsOverviewCards.xaml  # 顶部概览卡片（库总数/总时长/最长游戏）
        ├── PlayStatusDistribution.xaml # 状态分布（游玩状态/游戏引擎/制作公司 三标签）
        ├── PlaytimeRanking.xaml     # 总时长 TopN 排行
        └── PlaytimeHeatmap.xaml     # 年度游玩强度热力图
```

## 4. 四大功能设计

### 4.1 游戏库游戏数量

- 计算：`GetAllGames().Count`。
- 展示：概览卡片 ①「库中游戏」，大数字 + 副标题「共 X 款 · Y 个本地安装」。
- 边界：`GetAllGames()` 返回的是快照，页面每次进入/刷新时重新获取。

### 4.2 游玩状态分布（含多标签扩展）

- 计算：按 `PlayType` 分组计数（6 组），同时预留 `Engine` / `Developer` 两个维度（对齐截图的三标签设计）。
- 展示：标签页（游玩状态 / 游戏引擎 / 制作公司）→ 下方为横向卡片流；每个分类项 = 图标 + 名称 + 数量（对齐截图视觉：深色卡片、卡通图标）。
- 交互：点击某个分类可下钻——将该状态筛选条件传给宿主游戏列表（复用 `IPotatoVnApi.AddFilter`，可选增强项）。
- 空数据：0 数量分类正常显示「×0」但置灰，保持布局稳定。

### 4.3 总时长最长游戏

- 计算：按 `TotalPlayTime` 降序排序，取 TopN（默认 Top10）。
- 展示：Top1 做成醒目「最长」卡片（游戏名 + 封面 + 总时长 + 游玩次数），其余为横向条形排行（条形长度 = 占总时长比例）。
- 数据口径：时长单位统一为小时（分钟换算，保留 1 位小数），排行旁标注「单位：小时」。

### 4.4 年度游玩强度热力图（GitHub 贡献图）

**算法步骤**（`GameStatsService.BuildHeatmap(int year)`）：

1. **聚合明细**：遍历 `GetAllGames()`，把每款游戏 `PlayedTime` 中属于目标年份的每一天（key 用文化无关方式解析，见下）累加到 `Dictionary<DateTime, int> dailyMinutes`。
2. **日历网格映射**：以「周一为一周起点」布局，列 = 一年中的 ISO 周序号，行 = 周一~周日；年初第一周从该年首个周一起始，与 GitHub 贡献图对齐。
3. **五档色阶**（按当日总分钟数）：

   | 档位 | 当日时长 | 颜色语义 |
   |------|---------|---------|
   | L0 | 0 分钟（无记录） | 基底灰 |
   | L1 | 1–59 分钟 | 浅 |
   | L2 | 60–179 分钟 | 中 |
   | L3 | 180–359 分钟 | 深 |
   | L4 | ≥360 分钟 | 最深 |

4. **年度切换**：年份下拉（取所有 `PlayedTime` 覆盖的年份集合，缺省定位最近有数据的年份）+ 左右箭头，切换时重算网格。
5. **单元格提示**：hover/点击显示「2026-03-12 · 共 4h 25m · 3 款游戏」（含当日游戏明细，可下钻）。
6. **边角说明**：底部色阶图例「少 → 多」；周一/周日行首标星期缩写，每季度首列标月份缩写。

**日期解析注意**：`PlayedTime` 的 key 是 `ShortDateString()`，格式随系统区域变化（如 `2026/3/12` 或 `2026-03-12`），聚合时用与宿主一致的 `Utils.TryParseDateGuessCulture` 容错解析，解析失败的天跳过并记日志。

**控件实现（推荐原生）**：用 `ItemsControl` + `UniformGrid` 生成 53×7 个圆角 `Border` 单元格，每个单元格挂 `ToolTip`；纯 XAML/C# 实现、零外部依赖、性能好、随宿主主题自适应。备选方案：WebView2 + ECharts（与现有 HTML 原型一致，交互更强但引入 WebView2 依赖）。

## 6. 技术实现要点

1. **入口**：侧边栏按钮 → `NavigateTo(typeof(GameStatsPage), "游戏统计")`；页面为 `Page` 子类，用 `XamlResourceLocatorFactory.PluginControlInit()` 初始化 XAML。
2. **异步计算**：页面 `OnNavigatedTo` 时在后台线程调 `GetAllGames()` + 聚合，完成后用 `_hostApi.InvokeOnMainThread` 切回 UI 线程刷新绑定集合。
3. **数据刷新**：页面每次进入重算（快照特性）；监听宿主消息 `GalgameEvents`（游戏增/删/改、游玩时长更新）触发局部刷新，避免手动点刷新。
4. **持久化**：`PluginData` 扩展 `int HeatmapYear`、`int HeatmapLevels` 等偏好；序列化含 `Version` 字段做版本迁移（遵循 `doc/data.md` 建议）。统计值本身不落盘。
5. **多语言**：复用 `PluginLocalization` + `Strings/zh-CN|en-US|ja-JP.json`，标签「游戏统计/游玩状态/未设置…」全部走资源键。
6. **可测试性**：`GameStatsService` 不依赖 UI/宿主，输入 `IEnumerable<Galgame>` 输出 DTO，可写纯单测（热力图网格对齐、时长聚合、状态计数、Top 排序）。
